# Reveal 与后台输入

## 拾取、几何与 Reveal

- Picker 使用 `WindowFromPoint`/`GetAncestor` 选择顶层窗口，过滤桌面、任务栏、自身及不支持目标；Esc 按下、重复及抬起均拦截且只取消一次。
- 领域几何统一使用物理屏幕像素，进程使用 Per Monitor V2 DPI manifest；UI 的 DIP 只在显示层转换。普通窗口、最大化和最小化按完整 placement 区分。
- Ghost 使用 `SW_HIDE`，临时控制工具窗口、置顶和 DWM 装饰；保留标题栏与缩放边框样式，避免浏览器因非客户区变化重排。Restore 还原原值。
- Reveal 支持圆形、矩形、圆角矩形。首次显示在隐藏时先应用 region，显示后再应用/校验；连续移动使用增量更新。光标与几何不变时跳过重复 native 更新。
- `SetWindowRgn` 成功后由系统拥有 HRGN；失败时由调用方删除。曲线 region 的右/下开区间须补偿，原始 region 恢复失败须明确返回错误。
- 为兼容重绘竞态，单次 region 更新最多重施/校验三次；该轮仍失败先安全隐藏，下个 tick 重试，连续三轮失败才通知。这不证明所有自绘窗口均兼容。

### Composition 与调度

`IRevealVisualHost` 隔离可选 `RevealEdgeOverlay`；`IVisibilityBackend` 保留可独立运行的硬边路径。默认 Reveal 为 144px 圆角矩形、16px 羽化、轻度模糊。Composition/Win2D 不抓屏：清晰核心保留，目标内容 region 外扩至羽化宽度的 70%，单一 backdrop 模糊配合渐变遮罩绘制外环。

Overlay 非激活、鼠标穿透、无任务栏项，并由当前目标拥有，防止点击目标后被其遮挡。宿主覆盖目标 bounds，目标切换/销毁后重建；遮罩按视觉参数缓存，与光标位置无关。移动只更新 visual offset 和外环 region，核心点击/滚轮仍到目标。设备、初始化或渲染失败时隐藏 overlay，将内容缩回硬边 region，不依赖视觉层执行恢复。

非 Reveal 轮询约 60 Hz，Reveal 按鼠标所在显示器当前模式及 Auto/60/90/120 上限调度，最高 120 Hz。显示查询按显示器缓存两秒，`WM_DISPLAYCHANGE` 使缓存失效，失败回退 60 Hz。Debug 每 120 个有效移动帧汇总有效 FPS、平均/P95/最大 tick 耗时和超预算帧数，不逐帧写成功日志。

## 实验性后台输入

当前实现是默认关闭的实验功能，使用方法见[实验说明](../product/EXPERIMENTAL_BACKGROUND_INTERACTION.md)。能力和实际验收必须分开：接口调用成功不证明目标完成操作，更不证明前台网页全程未失焦。

### 技术路线状态

当前采用目标进程内、限定 UI 线程的独占输入桥接：Reveal 期间将输入交给目标 B，保留 A 的真实前台；取消 Reveal 后恢复 A 的正常输入。无需完整虚拟机、虚拟屏幕或 MouseMux，也不要求 A/B 同时接受独立输入。普通操作经过目标自身消息循环，避免依赖某个编辑器的复制、选区等专用命令。

维护者确认最新试用版的本轮反馈场景已无异常，基本操作、编辑交互及菜单修正支持了该方向的可行性，选型探索阶段告一段落。当前正常构建、发布及安装包携带原生组件，App 通过现有实验设置启用该路径，不再依赖专用构建或启动参数；实验设置默认关闭，关闭时不加载或注入组件。后续工作转向兼容性扩展，中文、系统弹窗和完整焦点证据等缺口统一维护在[质量边界](../quality/KNOWN_LIMITATIONS.md)。

### 会话与输入归属

`BackgroundInteractionSession` 负责身份、受保护前台和输入归属；Platform 使用独立 Hook 消息线程及代次输入队列。主业务仍在 Avalonia UI 线程；开始实验交互时，`ExclusiveInputBridge` 向已登记目标 UI 线程加载原生组件，不使用 `AttachThreadInput` 借用前台输入上下文。组件加载延迟到交互准备，缺失或校验失败时拒绝开始并提示修复安装，不回退重试其他输入路线。

生产输入只有 `ExclusiveInputBridge` 一条路线，没有控件适配、UIA 自动化或直接后台消息的替代后端。输入写入有界队列，由目标正常消息循环处理快捷键与字符，返回仅表示入队。取消丢弃未执行输入，已执行中的消息返回后清理，不依赖控件编辑命令。目标侧模块驻留、租约失效透传和作用域限制仍保留；实现不构成所有应用或全程焦点兼容性结论。

仅为已登记目标临时设置 `WS_EX_NOACTIVATE`，结束时恢复快照中该位的原值，保留其他位。持续模式只允许 Toggle Peek：先等待有效独立前台和已按输入释放，再准备 Hook/目标，最后显示 Reveal。准备期间的新输入消费但不排队重放，准备前属于 A 的按键抬起仍交给 A。

正常移出/返回可结束/重建持续会话；真实失焦、投递失败、目标失效或未管理弹窗清除显示意图，须重新手动 Peek。独占桥接只将同 PID、同 UI 线程、所有者链回到 B 的指定类型菜单纳入输入范围；初次显示先延后到快照登记及裁剪完成，硬件归属层仅为独占桥接启用无按钮移动转发，右键释放后继续更新悬停与光标；菜单显示后立即刷新当前点，系统移动仍透传以驱动 Reveal 跟随。主窗口和菜单共用随鼠标移动的 Reveal，扩展表面仅用于包含跨出 B 的菜单，根窗口与浮层分别使用各自的局部坐标；宿主先将自己的浮层独立置顶，目标再保留 Z 序显示菜单，目标不引用宿主浮层 HWND。菜单关闭仅消费匹配的抬起，不作为根窗口身份失效；根身份变化仍停止。取消时先在激活保护内关闭菜单，再释放实际按下。原生系统菜单及其他弹窗仍保留拒绝，具体类型见本页原生桥接与菜单一节。设置、选窗、恢复和退出取消等待/准备/交互，恢复开始后不再追加隐藏。

只为实际投递的原生按下发送抬起。硬件归属与投递账本独立，释放尾部最多两秒，不因后续输入无限延长。停止清除接收者、修饰键及旧代次输入；未支持操作与真实失败分别处理，结果不确定时不重放。

### 原生桥接与菜单

- 通过目标 UI 线程的 `WH_CALLWNDPROC` 加载桥接 DLL。只处理已验证身份的根窗口、同线程子控件及下述菜单，不默认提权；拒绝 x86、GS 自身和 A/B 同进程。
- 桥接仅替换目标已加载的非 Windows 模块中部分 User32 普通及延迟导入表条目：局部焦点/激活、键状态、光标、鼠标捕获、消息位置、字符翻译和指定菜单的创建/显示。只在所选线程的有效会话中生效；不修改执行代码，不钩 A，不连接渲染器或私有接口。
- 输入写入容量 128 的有界队列，`WH_GETMESSAGE` 在 B 的正常消息循环中还原消息，让应用先处理快捷键，再按其 `TranslateMessage` 调用生成字符。桥接返回只表示入队，不等待每次输入处理。目标尝试 Win32 激活/真实设焦点时由该线程 CBT 守卫拒绝。
- 菜单支持限于与 B 同 PID、同 UI 线程、所有者链回到 B 的启用、无标题栏且不穿透的 `Chrome_WidgetWin_1` 弹出窗口（Chrome/Electron Views 菜单及其子菜单）。指定窗口的首次显示先被延后；Platform 捕获完整快照并加入同一 Watchdog 恢复清单，设置与鼠标 Reveal 一致的裁剪，再通知目标线程非激活显示在浮层下。未准备好的菜单不接收鼠标操作，取消或失败不重放显示与输入。带标题栏对话框、其他线程、其他所有者和原生 `#32768` 系统菜单仍不纳入。
- 菜单和主窗口共享随鼠标移动的 Reveal，不完整展示菜单，也不冻结区域；菜单伸出 B 时扩展可交互表面和浮层宿主范围。按当前 Z 序及窗口矩形命中，独立于上一帧裁剪。宿主先将自己的浮层非激活置顶，不联动所有者 Z 序，再提交菜单就绪；目标仅显示自身菜单，保留 Z 序，嵌套显示回调也不能将菜单置顶。桥接协议不传递浮层 HWND，避免普通权限目标引用管理员宿主浮层作为 `hWndInsertAfter` 时返回拒绝访问。所有菜单窗口修改前均已登记快照，隐藏/销毁后还原或移除辅助恢复资料，保持 schema 不变。
- 菜单准备或显示失败仍保护退出，不重试不确定操作；诊断 operation 区分区域读取、显示和显示后区域重设，不记录菜单文本或输入内容。
- 独占桥接在硬件归属路由显式启用无按钮移动转发，拖动结束或右键松开后仍持续发送位置、悬停与光标更新；准备、停止和关闭实验交互时不启用此路由。系统移动仍透传以驱动 Reveal 跟随，不产生第二个系统光标。刚进入 Reveal 即初始化光标；菜单完成裁剪和显示后，在激活守卫内通过正常消息循环立即刷新当前点的悬停和光标，不要求额外点击或移动。菜单在按下时关闭或销毁，仅消费该菜单匹配的抬起并清理目标线程账本，不把菜单关闭当成根目标身份改变，也不向复用的 HWND 投递。
- 沿用现有 Hook：键盘和鼠标按钮/滚轮在交互时独占，系统光标移动仍用于 Reveal 跟随，不提供第二个独立系统光标；移出 B 及有效菜单范围后结束本次交互。菜单的真实激活/设焦点仍由同一 CBT 守卫拦截。
- 取消立即丢弃尚未执行的队列项，并在激活保护内先取消菜单；鼠标释放交由 native 清理，不额外入队一次可能触发菜单项的普通抬起。已在执行的消息返回消息循环后释放实际执行过的按下、还原导入表并解除 Hook。为避免遗留回调指向已卸载代码，目标中的桥接模块会驻留到目标正常退出；它在会话外透传，不影响原调用。桥接失败或不再需要时可正常关闭并重新打开该测试目标。
- GS 在 UI 交互轮询中续租，租约两秒。GS 退出、UI 停止续租、租约过期或 A 真失焦后目标侧虚拟接口透传；过期租约不能被迟到心跳复活，须重新建立会话。超时使会话失效，不重发不确定操作。超时/崩溃时导入条目和已加载模块可能仍驻留，但不再虚拟化；Watchdog 仍负责窗口样式/可见性恢复。
- 尚未覆盖动态解析的 API、新加载模块、其他 UI 线程、Raw Input、框架私有焦点、系统菜单/文件弹窗和中文组合输入。Win/Alt 系统组合与 IME 请求拒绝。Ctrl 编辑操作经过应用普通消息循环，剪贴板由目标按用户操作处理，桥接自身不读写剪贴板；默认复制/粘贴结果和真实 Chromium/Electron 兼容性待逐项验证。
- 本路径验证的是局部输入虚拟化能否有用，不承诺任意程序全程无失焦。独占输入不会消除应用内部焦点依赖。
