# GhostSlacking 开发实施计划

本文定义阶段目标和验收操作；当前状态、通过记录、缺陷及待办只维护在[实施状态](IMPLEMENTATION_STATUS.md)。实现机制与保护约束见[架构](ARCHITECTURE.md)，构建和发布规则见 [AGENTS.md](../AGENTS.md) 与[开发流程](DEVELOPMENT_WORKFLOW.md)。

## 1. 实施策略

保留 Phase 0–4 作为技术验证、核心闭环、可靠性、产品化和可选渲染的阶段划分。后续工作以状态文档中的真实缺口排序，不重新执行已落地的搭建任务，也不将日常可用等同于专项兼容性验收。

## 2. 技术基线与范围

Windows 10/11 x64、.NET 8、Avalonia/FluentAvalonia、Core/Platform/App 分层与独立 Watchdog/Updater。单目标 Pick → Ghost → Peek → Restore，物理像素几何、region 裁剪及可回退 Composition。修改前完整快照，恢复前验证 HWND/PID/启动身份；不默认提权、不注入、不截图，不承诺防监控或任意特殊窗口兼容。多窗口规则、账户和云同步不在当前范围。

实验后台交互的后续目标是通用机制可行性研究；当前实现仍依赖控件能力。研究应先证明跨技术栈操作、焦点与恢复边界，不默认按应用不断追加特例；本轮维护不实施研究或新增路径。

## 3. Phase 0 — Technical Spike

目标：确认普通窗口的拾取、region、坐标、输入与恢复路线可行。任务覆盖顶层 HWND、原 region/placement/style 捕获、隐藏/局部显示、真实点击/滚轮、权限及不同窗口重绘差异。门槛：有可复现的基本闭环和明确限制，失败时不遗留不可恢复窗口；不要求另建或恢复已退休的 Spike 工程。

## 4. Phase 1 — Ghost Core

目标：单窗口闭环。任务覆盖领域状态、Picker 拦截/取消、身份和几何观察、Hold/Toggle Peek、显隐与最终恢复、托盘/快捷键和基本配置日志。门槛：重复操作不丢状态，选择/取消/切换目标正确，区域跟随可交互，原位置/大小/显示及任务栏状态可恢复，关闭目标不操作复用 HWND。

## 5. Phase 2 — Reliability

目标：常见失败后可安全恢复且原因可诊断。任务包括幂等恢复、稳定性校验、带会话和版本的 Watchdog 清单/心跳、会话结束前尽力恢复、DPI/多屏和完整性级别诊断。门槛：异常恢复、身份拒绝、目标生命周期、缩放变化和权限矩阵通过，失败不无限纠正或隐藏/显示循环；两小时无持续资源增长。

## 6. Phase 3 — Productization

目标：普通用户可安装、设置、更新和排查问题。任务包括托盘/设置/HUD、配置迁移与损坏回退、保存/取消、单实例/HKCU 开机启动、受限日志与导出、签名 NSIS 更新和用户说明。发布清单签名与 Windows Authenticode 分开验收。门槛：设置重启保留、错误可理解、干净系统安装/更新/卸载及失败回退通过，权限/隐私/兼容性说明准确。

## 7. Phase 4 — Advanced Rendering

目标：提供可关闭、可回退的软边与模糊，不改变恢复契约。任务包括独立视觉宿主、非激活鼠标穿透 overlay、位置无关遮罩缓存、region 首次/增量路径、自适应帧率和性能测量。门槛：视觉稳定、核心交互正确，初始化/设备失败可回硬边，目标切换后无旧宿主或资源持续增长。属于可选渲染，不以它替代可靠性验收。

## 8. 验收记录约定

每项记录 GS 完整版本/提交、OS/应用版本、权限、DPI/屏幕配置、起止时间、操作、实际结果与日志路径。结果使用通过、部分通过、失败、未测或条件不足；用户版本未提供时如实注明。自动化、隔离控件试验与真实应用人工结果分别记录。

测试使用可关闭的空白文档，先保存工作。异常恢复只结束 GS 主进程并保留 Watchdog，不能结束目标或用“结束进程树”代替。缺少环境的场景不要求现场补齐，但必须保留未验证状态。

### 9.4 实验性后台交互

准备：使用[当前操作说明](EXPERIMENTAL_BACKGROUND_INTERACTION.md)，A 保持[焦点诊断页](../tools/background-focus-probe.html)前台并重置记录，B 使用空白测试内容。记录完整时间区间，结束后主动切回 A 造成的事件单独排除。通过要求 B 结果正确、A 全程 `hasFocus=true` 且无 blur/hidden、系统前台无异常变化、结束无卡键/样式残留；最终焦点回到 A、日志成功或 50ms 采样都不能单独证明通过。

| 检查 | 怎么操作 | 预期与记录 |
| --- | --- | --- |
| 冷启动/前台等待 | 隐藏 B 后直接 Peek，另测先聚焦 A 再 Peek；等待时取消/恢复/打开设置 | 无有效前台时不安装拦截，聚焦 A 后可自动继续；取消不再准备或追加隐藏。 |
| 持续模式 | 反复 Peek、移出/返回，准备时快速点击/滚轮/按键；准备前按住 Ctrl/Shift/鼠标再释放 | 准备期无普通输入泄漏或重放，A 的原有抬起保留；正常结束不重复通知。 |
| 文本/鼠标 | 按应用分别测首次/重复点击、英文、滚动、正反/跨行拖选、双击/Shift、Ctrl+C/X/V/Z/Y | B 实际结果正确且 A 事件正常；每个动作单列，拒绝不记成功，不发送真实聊天。 |
| 语义按钮 | 单击按钮/选项/树，重复抬起、拖出再返回松开、快速合并移动 | 未拖动完整抬起只执行一次，拖动不误触；输入框单击不调用系统焦点。 |
| 空框粘贴保护 | 点击严格空框后 Ctrl+V 纯文本，再试已有草稿/空格/换行/富子项/只读；点击其他控件后直接粘贴 | 仅可确认空白可写框试验赋值，编辑器状态应同步；其余明确拒绝且不整框覆盖/串用旧目标。 |
| 停止与尾部 | 按住键/鼠标时用 Peek、交互键、移出、恢复、设置、退出和目标关闭结束；两秒内外再试 Shift/Ctrl/Win+Space | 无卡键或输入误投，结束后系统正常处理；字符/编辑命令不额外发抬起，恢复后不再隐藏。 |
| 真失焦/弹窗/身份 | A 瞬间离开再返回，B 主动激活/创建 owner 弹窗、关闭/重启；按适用权限和 DPI 对比 | 收起并清除显示意图，不自动重试、修改弹窗或新身份；保留实际事件。 |
| 异步/超时 | 连续命中/拖选后停止并重开，使用隔离工具验证挂起与旧回执 | 旧代次结果不重放；只读失败和修改结果不确定分开，后者停止且不切其他写入路线。 |
| 设置/图标 | 实验开关/持续保存取消重启，持续+Hold，图标各状态/主题/导航展开收起 | 默认关闭、异常组合被阻止，图标颜色/尺寸一致；缩放渲染不代替实际混合 DPI。 |
| 中文研究 | 按[原型步骤](../tools/BackgroundImeProbe/README.md)分别试 TSF 和独立层 | B 提交正确、A 完整焦点正常、退出后布局/Shift 正常才算该原型通过，不推广生产。 |

诊断日志位于 `%LOCALAPPDATA%\GhostSlacking\logs`：

- `BackgroundStart` 区分等待前台、释放、准备和拒绝；`AwaitingForeground` 不等于输入失败。
- `BackgroundInteraction phase=Preparing/Ready/Active` 记录阶段；`BackgroundForegroundEvent` 和 `ForegroundChanged` 记录实际失焦，不能用 UIA 超时代替。
- `BackgroundAutomationResult` 的 generation/operation、kind/stage、queueMs/elapsedMs、HRESULT、mutation/rejection 用于区分命中、能力、执行和校验；修改前预算 1.5 秒，修改后 500ms 结果不确定即停止。
- `BackgroundAutomationCancelled` 表示旧请求作废，不证明已发操作撤销。`BackgroundSemanticTarget`、`PasteEmpty`、`SetEmptyValue`、`VerifyValue` 区分语义路线和空框写入阶段。
- `prepare/reset/restored` 的焦点/布局及可用时的 `imeOpen` 仅作诊断；IMM 代理值不能代表所有 TSF 状态。保存时间、能力、错误码，不能保存正文、控件名称或剪贴板内容。

## 10. 里程碑

M0 可复现的技术路线；M1 可演示基本闭环；M2 可靠性矩阵通过；M3 干净环境产品化验收通过；M4 可回退渲染与兼容/性能证据。当前完成度仅见状态文档，不在此重复维护。

## 11. Definition of Done

实现遵守项目边界、修改前快照和恢复前身份检查；Win32 资源所有权/失败清理明确；自动化和适用人工矩阵有结果，文档与行为一致。未完成能力、缺陷、缺少环境的验收必须显式保留，不能通过改状态或删除要求宣布完成。

## NSIS EXE 安装与更新验收矩阵

当前用户安装、系统 .NET 8 x64 依赖、发布签名；旧 MSI 须安全退出后手动卸载，新 EXE 不自动迁移。下面只定义操作与预期，实际结果统一见状态文档。

| 场景 / 操作 | 预期与记录 |
| --- | --- |
| Win10/11 标准用户首次安装 | 无 GhostSlacking UAC、默认用户目录；开始菜单默认开启/桌面默认关闭、完成页可选启动，记录完整版本与权限。 |
| 无 .NET / x86-only / 仅 .NET 9/10；对比含兼容 x64 Core Runtime 的 .NET 8 SDK/Desktop Runtime | 缺少 .NET 8 x64 时阻止并提供官方地址，不自动下载；满足运行时可启动，记录安装环境。 |
| 存在旧 MSI | 按 UpgradeCode 拒绝并保留旧程序/注册，不自动卸载。 |
| 中文/空格路径；网络目录/reparse point/非空无归属目录 | 合法路径快捷方式/安装/更新/卸载一致，不安全目录拒绝且不改无关文件。 |
| Ghost/Peek 中更新、覆盖安装或卸载 | 恢复所有受控窗口，等待 App/Watchdog 安全退出后才改文件，记录目标原始状态及恢复结果。 |
| 身份复用、恢复失败、Watchdog 不退出或跨权限残留 | 30 秒内失败，不强杀 App/Watchdog，不改旧程序。 |
| 文件占用、目录切换异常、安装中断 | 原程序和注册可回退，下次安装恢复事务；用户数据保留。 |
| beta → RC → stable、同版本及降级 | 按完整 SemVer 排序，允许同版本修复、拒绝降级；应用实际版本与包体一致。 |
| 应用内下载/安装、取消/失败/启动失败 | 校验签名和哈希；失败不误报成功，尝试重启且保留所需备份；记录失败阶段/结果文件。 |
| 更新通知点击与悬停 | 暂停/恢复计时正确，仅执行一次，更新窗口可再次打开。 |
| 卸载、开机启动；安装后移除 .NET 再卸载 | 删除对应程序/快捷方式/启动项，保留用户数据，无 .NET 仍可卸载。 |
| 本地安装/更新各十次 | 排除下载/人工，正常流程目标 30 秒内、无约 90 秒固定等待；记录各阶段耗时。 |

原生事务自动化入口为 `pwsh ./tests/Installer.Tests.ps1`；完整 Release .NET 与元数据检查要求见 AGENTS。事务自动化不等于干净系统、真实目标或发布包兼容性通过。
