# GhostSlacking 开发实施计划

> 目标版本：GhostSlacking V0.1  
> 平台：Windows 10/11  x64  
> 主路线：C# + .NET + Avalonia/FluentAvalonia UI + Win32 P/Invoke
> 首个可用渲染方案：`SetWindowRgn`

> 当前状态（2026-09-09）：Phase 1 实现完成；Phase 2 的 Watchdog v1 已完成、其余可靠性工作进行中；Phase 3 产品化代码基本完成；Phase 4 Composition 羽化原型已接入。真实窗口兼容性、DPI/权限矩阵、长时间运行和干净系统安装验收仍未完成，详见 [实施状态](IMPLEMENTATION_STATUS.md)。

## 1. 实施策略

按“先验证最关键风险，再补可靠性，最后产品化”的顺序推进。每个 Phase 都应产出可运行结果和明确的停止/继续判断，避免在核心技术未经验证前投入设置系统、复杂 UI 或高级渲染。

```text
Phase 0  Technical Spike       验证 HWND、region、坐标、交互、恢复
   ↓
Phase 1  Ghost Core            做出单窗口可用闭环
   ↓
Phase 2  Reliability            Watchdog v1 已完成，其余异常/DPI/权限验收进行中
   ↓
Phase 3  Productization         托盘、设置、配置和发布代码基本完成
   ↓
Phase 4  Advanced Rendering     Composition 外扩羽化原型已实现，验收进行中
```

## 2. 技术基线与范围

### 2.1 基线

- Windows-only；
- C#、现代 .NET LTS、Avalonia/FluentAvalonia；
- Win32 API 集中封装在 Platform 层；
- 单目标窗口优先；
- 不注入、不截图、不依赖目标应用 SDK；
- 核心裁剪使用 `SetWindowRgn`；Composition 外扩羽化是可选视觉层，失败时回退硬边 region；
- 所有修改先保存快照；异常退出由 Watchdog 尽力恢复，正常退出按 `RestoreOnExit` 设置恢复。

### 2.2 V0.1 必须交付

- Window Picker；
- 单窗口 Ghost/Reveal/Restore 状态机；
- Hold-to-Peek 和按下切换两种 Peek 模式；
- 圆形、矩形或圆角矩形 Reveal 随鼠标移动；
- 区域内点击/滚动的兼容性验证；
- 当前窗口位置和尺寸跟踪；
- 托盘入口和全局快捷键；
- 基本配置和日志；
- 手动 Emergency Restore；
- 正常退出和常见异常路径的恢复。

### 2.3 V0.1 不做

- 多窗口同时管理；
- 抓屏式软边、静态模糊副本、实时窗口克隆和复杂动画；
- 云同步、账户、插件、规则引擎；
- OCR、截图、录制、远程控制；
- 绝对防录屏/防监控；
- 为兼容个别特殊应用而引入复杂注入或驱动。

## 3. Phase 0 — Technical Spike（已沉淀到当前实现）

### 3.1 目的

本阶段的验证结论已沉淀到当前 Core/Platform/App 实现：普通窗口采用 `SW_HIDE` 进入 Ghost，Reveal 使用 `SetWindowRgn`，并保留完整快照用于恢复。原始 Spike 工程未单独保留；真实窗口结论仍以手工矩阵为准。

以下任务表是实施拆解和结果来源，不是尚未开始的待办列表。

### 3.2 任务

| 编号 | 任务 | 依赖 | 产出 |
|---|---|---|---|
| 0.1 | 创建最小 .NET Avalonia 实验项目 | .NET SDK | 可启动实验程序 |
| 0.2 | 封装 `WindowFromPoint`、`GetAncestor`、`GetWindowRect`、PID 查询 | 0.1 | 基础 HWND 工具 |
| 0.3 | 封装 `CreateEllipticRgn`、`SetWindowRgn`、`DeleteObject` | 0.1 | region 实验器 |
| 0.4 | 实现鼠标轮询和屏幕坐标到窗口本地坐标转换 | 0.2 | 圆形跟随 |
| 0.5 | 实现 Peek Key 按下/抬起和最小状态机 | 0.4 | Hold-to-Peek |
| 0.6 | 验证空 region/隐藏策略与 Reveal 策略 | 0.3 | Ghost 策略结论 |
| 0.7 | 保存并恢复原始 region、可见状态和必要 style | 0.6 | 可恢复实验 |
| 0.8 | 在目标窗口关闭、实验程序退出时验证清理 | 0.7 | Spike 记录 |
| 0.9 | 在多 DPI、双屏和权限不同窗口上重复验证 | 0.4–0.8 | 兼容性矩阵 |

### 3.3 Spike 验收标准

- 能选择记事本、资源管理器、Chrome/Edge 中至少两个窗口；
- Reveal 圆形位置与光标相符，移动时无明显跳动；
- 松开 Peek Key 后目标窗口回到 Ghost；
- 至少一个普通窗口在圆形区域内可以点击或滚动；
- 可恢复原始 region/显示状态；
- 目标窗口关闭后程序不崩溃、不持续操作失效 HWND；
- 在 100% 和 150% DPI 下坐标误差不超过一个明显 UI 像素级偏差；
- 明确记录空 region 与 `ShowWindow` 策略的优缺点；
- 若核心交互在普通窗口上不可接受，应在此阶段停下来调整技术路线，而不是直接扩大产品范围。

### 3.4 Phase 0 结束门槛（历史判定口径）

进入 Phase 1 前，region 路线和恢复路径必须在至少两类普通窗口上验证；特殊窗口失败记录为边界，不阻塞 MVP。当前实现已沿用该路线，但仍需完成第 9 节列出的完整手工矩阵。

## 4. Phase 1 — Ghost Core（实现已完成）

### 4.1 目的

把 Spike 重构为可测试的单窗口核心，形成从拾取到恢复的完整产品闭环。

本阶段的代码和自动化测试已完成；剩余真实窗口验收列在第 9 节和实施状态文档中。

### 4.2 任务拆解

#### 4.2.1 工程和领域层

- 建立 `App`、`Core`、`Platform` 项目边界；
- 定义 `GhostWindowProfile`、`WindowSnapshot`、`RevealSettings`；
- 实现应用级状态机和状态转换守卫；
- 定义 `IWindowApi`、`IInputSource`、`IVisibilityBackend`、`IClock` 等最小接口；
- 为状态转换、坐标计算、半径边界和配置校验编写单元测试。

#### 4.2.2 Window Picker

- 实现拾取模式开始、取消和完成；
- 根据屏幕点获取顶层窗口；
- 排除 GhostSlacking 自身、桌面、任务栏和不可操作对象；
- 展示轻量边框高亮；
- 选择后显示窗口标题/进程名摘要，避免误选；
- 选择期间处理目标销毁竞态。

#### 4.2.3 WindowTracker

- 非 Reveal 以约 60 Hz 轮询 HWND、rect、最小化和进程身份；Reveal 跟随鼠标显示器刷新率并限制在最高 120 Hz；
- 仅在光标或几何信息变化时请求 region 更新；
- 目标失效时发出清理事件；
- 目标移动、缩放、跨屏时保持 Reveal 位置正确。

#### 4.2.4 TriggerEngine

- 用 `RegisterHotKey` 支持 Pick、Restore、Emergency Restore；
- 实现 Peek Key 按下/抬起；
- 合并重复输入，确保释放事件优先；
- 处理快捷键注册失败和冲突提示；
- 将输入转换为领域事件，不让输入层直接修改窗口。

#### 4.2.5 Visibility/Region

- 实现 Ghost、Reveal、Restore 三条核心命令；
- 实现圆形 region 生成、边界求交和句柄生命周期；
- 保存原始 region 数据并支持清除/还原；
- 避免光标未变化时重复调用 `SetWindowRgn`；
- 记录每次 native 调用失败的错误码。

#### 4.2.6 最小托盘体验

- 创建 Avalonia `TrayIcon` 和最小原生托盘菜单；
- 显示当前目标及 Ghost/Reveal 状态；
- 提供 Pick、Restore、Restore All、Exit；
- 退出时先进入恢复流程，再结束消息循环。

### 4.3 Phase 1 依赖

- Phase 0 已确认 region 路线可行；
- 已确定进程 DPI 感知方式；
- 已确定默认快捷键和 Peek Key 的输入实现；
- 已明确原始 region 的保存/恢复数据结构。

### 4.4 Phase 1 验收标准

- 用户可以从托盘进入 Picker 并选择一个普通顶层窗口；
- 选中后窗口默认不可见，不影响目标进程继续运行；
- 按配置的 Peek 模式且光标在目标范围内时出现所选形状的 Reveal；
- 光标移动、窗口移动和窗口缩放后 Reveal 几何正确；
- 松开按键、移出目标范围、Restore 或切换目标都会恢复正确状态；
- 圆形区域内至少完成点击、滚轮中的一种真实交互；
- `Restore All` 可恢复所有当前版本已修改窗口；
- 核心状态机和几何计算有自动化测试；
- 无明显的 GDI region 泄漏或高频无效更新。

## 5. Phase 2 — Reliability（部分完成）

### 5.1 目的

把“能跑”变成“出错时也不会把用户窗口留在异常状态”。Watchdog v1 已落地；本阶段剩余工作集中在生命周期、恢复、DPI、权限、诊断和真实环境验收。

### 5.2 任务拆解

#### 5.2.1 RecoveryManager 加固

- 为快照增加 schema version、PID 和进程启动标识；
- 恢复前再次校验 HWND/PID/进程身份；
- 将恢复拆为可独立报告结果的步骤；
- 实现幂等 `RestoreWindow` 和 `RestoreAll`；
- 覆盖切换目标、目标关闭、目标重启、应用退出等路径；
- 处理“只修改成功一部分”的中间态。

#### 5.2.2 异常与进程生命周期

- Avalonia 调度线程异常和正常退出已接入主进程恢复/关闭流程；AppDomain 未处理异常当前仅保留诊断输出，异常终止恢复由 Watchdog 负责；
- 捕获注销/关机通知，尽力提前恢复（未完成）；
- 发生恢复失败时停用自动重试并显示明确操作入口；
- 将最后一次恢复状态写入本地诊断日志。

#### 5.2.3 Watchdog

- [已完成] 新建最小 `GhostSlacking.Watchdog` 进程；
- [已完成] 设计带版本号和会话 ID 的当前用户本地命名管道 IPC；
- [已完成] 主进程发送启动握手、心跳和恢复清单；
- [已完成] 主进程正常退出前发送清理完成消息；
- [已完成] 心跳超时后验证 HWND、PID、进程启动身份和快照版本，再执行安全恢复；
- [部分完成] Watchdog 启动、IPC 失败和版本不兼容已有日志；真实异常终止和用户侧诊断反馈仍需手工验收。

#### 5.2.4 DPI 与多显示器

- [已完成] 设置 Per Monitor DPI Awareness V2；
- [待验收] 测试负坐标、不同缩放、跨屏移动和热插拔显示器；
- [已完成] 将所有核心几何统一到物理屏幕像素；
- [已完成实现/待手工验收] 对 DPI 变化和 rect 变化重新计算 region。

#### 5.2.5 权限和兼容性

- [部分完成] native 操作失败已有错误码和用户反馈；目标完整性级别的专门诊断仍未完成；
- [待补齐] 对高权限目标给出更具体的“需相同权限运行”提示；
- [已完成] 不默认提升管理员权限；
- [待验收] 对 Electron、浏览器、自绘窗口、全屏应用分别记录测试结果；
- [已完成实现/待扩充矩阵] 将不支持的窗口类型转为可理解的非阻断错误。

### 5.3 Phase 2 验收标准

- 主进程常见异常退出后，Watchdog 能恢复已登记且身份匹配的目标；
- 目标窗口关闭、PID 变化或 HWND 被复用时不会误恢复到新窗口；
- 退出、切换目标、Restore All 的恢复操作可重复执行；
- 100%/125%/150% DPI 和双屏混合缩放通过测试矩阵；
- 高权限窗口失败时不会导致主进程卡死或无限重试；
- 日志足以定位“哪一个 native 操作、对哪个目标、因何失败”；
- 长时间运行至少 2 小时无持续句柄增长、明显 CPU 升高或状态漂移。

## 6. Phase 3 — Productization（主要实现已完成）

### 6.1 目的

在核心可靠后补齐可日常使用的托盘、设置、配置、发布和用户反馈，不改变核心窗口技术路线。

### 6.2 任务拆解

- [已完成] 完善托盘菜单、状态文字和非激活错误/信息提示；
- [已完成] 增加 Avalonia + FluentAvalonia 设置页：Peek Key、最大 Peek 帧率、Reveal Diameter、形状、羽化、模糊、开机启动、退出恢复、日志级别和全局快捷键；
- [已完成] 使用 schema version 为 4 的 JSON 配置，并对损坏配置提供回退；
- [已完成] 增加启动单实例互斥，避免多个主进程同时修改同一窗口；
- [已完成] 完善 Emergency Restore 快捷键和托盘入口；
- [已完成] 增加 MSI 安装/卸载、快捷方式和开机启动选项；
- [已完成] 发布脚本、版本信息、受限滚动日志、日志诊断包导出和已保存配置导出；
- [部分完成] 已有最小权限说明和 GitHub Actions 发布流程；代码签名策略尚未落地；
- [已完成] 编写用户可读的兼容性和隐私说明；
- [待验收] 完成干净 Windows 环境安装、升级、卸载和手工回归清单。

### 6.3 产品化验收标准

- 首次启动无需复杂配置即可完成 Pick → Ghost → Peek → Restore；
- 设置修改在重启后保持，损坏配置不会阻止程序启动；
- 退出时默认恢复行为与设置一致；
- 快捷键冲突、权限不足、目标失效都有可理解反馈；
- 只有一个主进程管理目标窗口；
- 安装包在干净 Windows 环境中可安装、启动、卸载；
- 产品文案明确说明硬边 region、兼容性范围和不具备防录屏能力。

## 7. Phase 4 — Advanced Rendering（原型已实现，验收进行中）

### 7.1 进入条件

Phase 4 不是 V0.1 的必要条件；当前已根据用户对 Reveal 周边可辨识度的反馈进入，并保留 region 硬边路径作为回退：

- 硬边明显影响观感；
- 高频 `SetWindowRgn` 更新在实际窗口上造成明显卡顿；
- 需要渐变透明、软边、动画或多个视觉层；
- 需要窗口缩略镜、局部放大或更稳定的视觉合成。

### 7.2 任务拆解

- [已完成] 通过 `IVisibilityBackend` 和 `IRevealVisualHost` 隔离窗口 region 后端与视觉层；
- [已完成] 使用非激活、鼠标穿透的 Windows Composition overlay；
- [已完成] 使用 `CompositionBackdropBrush` 和 Win2D 效果描述实时模糊，不读取或保存目标像素；
- [已完成] 将目标内容 region 外扩到羽化宽度的 70%，用可选的单一 GPU 模糊等级在原始清晰边界之外平滑渐入、扩散和淡出；
- [已完成] 使用自适应最高 120 Hz Reveal 调度、首次/增量 Reveal 分流和位置无关遮罩缓存，消除连续移动中的重复显示、同步重绘与边缘资源重建；
- [待验收] 比较 CPU、GPU、内存、延迟和兼容性；
- [已完成] 保留 Region Backend 作为兼容和回退路径；
- [已完成实现/待手工验收] 视觉层未改变 Trigger、Tracker、Recovery 和产品状态机。

### 7.3 Phase 4 验收标准

- 新后端可以在不修改核心状态机的情况下替换；
- 软边/渐变在目标测试窗口上稳定；
- GPU/内存开销有实测数据；
- 后端失败时可回退到 region 或安全退出 Reveal；
- 不因高级渲染引入截图持久化、进程注入或不必要的服务端依赖。

## 8. 依赖与风险清单

| 风险 | 影响 | 最早验证阶段 | 应对 |
|---|---|---|---|
| 目标窗口不接受/不稳定处理 region | 核心体验失效 | Phase 0 | 先测多类普通窗口，保留兼容性边界 |
| 原始 region 保存不完整 | 恢复破坏用户窗口 | Phase 0/1 | 快照数据化、恢复前验证、专测原始 region |
| Hold Key 输入方案误触发 | Reveal 不稳定 | Phase 0 | 低级 Hook/键状态轮询二选一并测去抖 |
| DPI 坐标混用 | Reveal 偏移 | Phase 0/2 | 进程级 DPI 感知，统一物理像素 |
| 高权限目标不可控 | 部分用户无法使用 | Phase 2 | 提示并支持用户明确提升权限 |
| 主进程崩溃遗留 region | 目标窗口异常 | Phase 2 | Watchdog + 安全恢复清单 |
| 高频 region 更新消耗 CPU | 体验卡顿 | Phase 0/1/4 | 显示器刷新率自适应且最高 120 Hz、首次/增量分流、遮罩缓存和限频计数器 |
| HWND 被系统复用 | 误恢复新窗口 | Phase 2 | PID + 启动标识校验 |
| 全屏/受保护窗口不兼容 | 兼容性投诉 | Phase 1/2 | 明确非目标，提供失败反馈 |
| 过早引入高级渲染 | 工期和复杂度失控 | 全阶段 | Phase 4 设进入条件 |

## 9. 测试矩阵

### 9.1 功能矩阵

| 场景 | 预期 | 类型 |
|---|---|---|
| 选择普通窗口 | 获取正确顶层 HWND/PID | 自动化 + 手工 |
| Ghost | 默认不可见，进程继续运行 | 手工 |
| Peek | 按配置的按住显示或按下切换模式工作 | 自动化 + 手工 |
| 光标移动 | 所选形状的 region 跟随且无明显偏移 | 手工 |
| 窗口移动/缩放 | Reveal 几何跟随新 rect | 手工 |
| 圆内点击/滚轮 | 至少一种交互可用 | 手工 |
| 移出目标范围 | 回到 Ghost | 自动化 + 手工 |
| Restore | 原始状态恢复 | 自动化 + 手工 |
| Restore All | 所有已修改目标尝试恢复 | 自动化 + 手工 |
| 目标关闭 | 清理状态，不继续调用 | 自动化 + 手工 |
| 快捷键冲突 | 注册失败且有反馈 | 手工 |

### 9.2 环境矩阵

| 维度 | 最低覆盖 |
|---|---|
| Windows | Windows 10、Windows 11 |
| DPI | 100%、125%、150% |
| 显示器 | 单屏、双屏、负坐标、不同缩放、60/75/120/144 Hz 混合刷新率 |
| 窗口 | Win32、浏览器、Electron、自绘窗口 |
| 权限 | 普通权限、管理员目标 |
| 生命周期 | 移动、缩放、最小化、关闭、重启目标 |
| 退出方式 | 正常退出、取消、异常退出、注销/关机尽力恢复 |

### 9.3 性能和稳定性矩阵

- Idle 运行 30 分钟：CPU、内存、句柄；
- Ghost 运行 30 分钟：目标应用仍正常工作；
- Reveal 持续移动 10 分钟：Auto/60/90/120 上限下有效帧率接近 `min(鼠标显示器刷新率, 上限, 120)`，P95 tick 不超过对应动态帧预算，并记录 region 调用次数；
- 鼠标跨越不同刷新率显示器、运行时切换显示模式及显示器插拔：两秒内或收到 `WM_DISPLAYCHANGE` 后更新目标帧率，查询失败回退 60 Hz；
- 长时间运行 2 小时：无持续资源增长；
- 快速按下/抬起 Peek Key 1000 次：无状态卡死；
- 快速移动/缩放窗口：无明显异常 region 或 UI 线程阻塞。

## 11. Definition of Done

一个 Phase 只有同时满足以下条件才算完成：

- 任务产出已合并到对应项目边界，命名统一为 GhostSlacking；
- 自动化测试、手工测试和已知限制均有记录；
- 关键 Win32 资源没有已知泄漏，失败路径有释放或恢复策略；
- 日志可以定位状态转换、目标身份和 native 调用错误；
- 不会因新增功能绕过 `VisibilityEngine` 或 `RecoveryManager`；
- 文档、配置 schema 和用户可见行为与实际实现一致；
- 对未支持窗口、权限失败和恢复失败有明确产品反馈；
- 代码在目标 Windows 版本上可构建、启动和退出；
- 任何未完成项都被标记为已知限制或下一 Phase 任务，而不是隐含在发布范围内。

## 12. 原始首个开发顺序（已完成，供回溯）

如果从零开始重建原型，最短验证路径如下；它不是当前剩余工作的待办清单：

```text
1. 建立最小 Avalonia 托盘/消息循环
2. 选择 HWND 并读取 rect/PID
3. 直接应用一个固定圆形 SetWindowRgn
4. 用 GetCursorPos 更新窗口本地区域
5. 加入 Peek Key 按下/抬起
6. 加入原始状态快照和 Restore
7. 在记事本、浏览器、Electron 窗口上测试
8. 再重构为 Core/Platform/Recovery 边界
9. 最后补设置、安装和 Watchdog
```

这条顺序能最快回答产品最重要的问题：GhostSlacking 的“默认消失、按需局部出现、区域内操作、随时恢复”是否在普通 Windows 窗口上成立。
