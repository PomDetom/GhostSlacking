# Windows 手工验收矩阵

## 验收记录约定

每项记录 GS 完整版本/提交、OS/应用版本、权限、DPI/屏幕配置、起止时间、操作、实际结果与日志路径。结果使用通过、部分通过、失败、未测或条件不足；用户版本未提供时如实注明。自动化、隔离控件试验与真实应用人工结果分别记录。

测试使用可关闭的空白文档，先保存工作。异常恢复只结束 GS 主进程并保留 Watchdog，不能结束目标或用“结束进程树”代替。缺少环境的场景不要求现场补齐，但必须保留未验证状态。

## 实验性后台交互

准备：使用[当前操作说明](../product/EXPERIMENTAL_BACKGROUND_INTERACTION.md)，A 保持[焦点诊断页](../../tools/background-focus-probe.html)前台并重置记录，B 使用空白测试内容。记录完整时间区间，结束后主动切回 A 造成的事件单独排除。通过要求 B 结果正确、A 全程 `hasFocus=true` 且无 blur/hidden、系统前台无异常变化、结束无卡键/样式残留；最终焦点回到 A、日志成功或 50ms 采样都不能单独证明通过。

| 检查 | 怎么操作 | 预期与记录 |
| --- | --- | --- |

| 设置/图标 | 实验开关/持续保存取消重启，持续+Hold，图标各状态/主题/导航展开收起 | 默认关闭、异常组合被阻止，图标颜色/尺寸一致；缩放渲染不代替实际混合 DPI。 |
| 中文研究 | 按[原型步骤](../../tools/BackgroundImeProbe/README.md)分别试 TSF 和独立层 | B 提交正确、A 完整焦点正常、退出后布局/Shift 正常才算该原型通过，不推广生产。 |

诊断日志位于 `%LOCALAPPDATA%\GhostSlacking\logs`：

- `BackgroundStart` 区分等待前台、释放、准备和拒绝；`AwaitingForeground` 不等于输入失败。
- `BackgroundInteraction phase=Preparing/Ready/Active` 记录阶段；`BackgroundForegroundEvent` 和 `ForegroundChanged` 记录实际失焦，不能用 UIA 超时代替。
- `BackgroundAutomationResult` 的 generation/operation、kind/stage、queueMs/elapsedMs、HRESULT、mutation/rejection 用于区分命中、能力、执行和校验；修改前预算 1.5 秒，修改后 500ms 结果不确定即停止。
- `BackgroundAutomationCancelled` 表示旧请求作废，不证明已发操作撤销。`BackgroundSemanticTarget`、`PasteEmpty`、`SetEmptyValue`、`VerifyValue` 区分语义路线和空框写入阶段。
- `prepare/reset/restored` 的焦点/布局及可用时的 `imeOpen` 仅作诊断；IMM 代理值不能代表所有 TSF 状态。保存时间、能力、错误码，不能保存正文、控件名称或剪贴板内容。
