# 第七轮：实验图标、语义点击与空白框纯文本粘贴

日期：2026-11-02。试用目录 `artifacts/background-interaction-round7/`，第六轮及之前的目录保留。配置 schema 10、通知自适应布局、完整快照和 Watchdog 协议不变。

## 本轮行为

- 实验图标重绘为 20 DIP 画布、约 0.85 DIP 线框烧瓶，仅保留轮廓与液面。实际导航生成的是 FluentAvalonia `FAPathIcon`；将该控件绑定到图标承载器随状态计算的前景色。保留完整画布，避免路径可见边界被放大后比字体图标更高、更粗。不单独减透明度。
- 每次点击重新按坐标命中并验证到 B 的祖先关系，不再用正文大范围缓存遮蔽输入框或按钮，也不回退到 B 中第一个文档。按钮按实际模式走 Invoke、Toggle、ExpandCollapse 或 SelectionItem，仅在无拖动的完整单击抬起时执行一次。合并移动保留最大偏移，拖出再返回不会误触。
- 编辑框与正文选区分离。普通输入框单击只登记后台接收目标，不调用 SetFocus，也不假装获得系统键盘焦点；双击/Shift/拖动才尝试文本选区。点击其他控件、目标几何变化、页面元素失效或停止会清除旧接收上下文。
- 用户显式 Ctrl+V 才读取 Unicode 纯文本（最大 1 MiB 剪贴板分配块），不改剪贴板。只允许当前命中的 Edit 控件、可写 ValuePattern、Value 精确为空，且文本树/嵌入子元素可证实无富内容。空格、换行和已有草稿均拒绝；不能确认时拒绝。读取剪贴板后再次检查身份和空白条件。
- 本轮的 SetValue 是有限空白框试验，不是光标插入。调用后读取值核对；不相符、写入后超时或真实失焦会停止，不重放。文本/剪贴板仅短暂留在操作内存，不写日志，不持久化。
- UIA 发现仍沿用 1.5 秒预算，修改后 500 ms 结果不确定即停止。COM 调用可能不受逻辑超时取消，主程序不阻塞 UI；新路线和卡死试验在独立探测工具中运行。

短提示：`先点输入框`、`仅限空框`、`内容受限`、`剪贴受限`、`控件受限`。日志区分 `BackgroundSemanticTarget route=...`、`PasteEmpty`、`SetEmptyValue`、`VerifyValue`，包含会话/操作号、能力、耗时和 HRESULT，不包含控件名称、正文或剪贴板内容。

本轮完整 Release 套件通过 352 项（Core 172、App 180，零失败/跳过），发布元数据检查通过；主程序和研究工具 Release 编译均零警告/错误。试用主程序 App/Platform DLL 与完整测试使用的 DLL 的 SHA256 一致。实际执行隔离窗口验证，结果摘要见交付包 `validation.json`，原始 TRX 和 JSONL 留在 `artifacts/background-interaction-round7/`。源码和试用说明不能代替实际应用验收。

| 路线 | 本机证据 | 适用边界 |
|---|---|---|

图标在实际设置窗口检查正常/选中/悬停/按下/禁用的控件画刷与参考 SymbolIcon 一致，浅深主题、导航展开/收起均覆盖；另生成 100/125/150/200% 的 16 张渲染图并人工查看。渲染缩放不等于实际混合 DPI 显示器验收。

试验中观察到：标准编辑器的 RangeFromPoint 也可能超过只读预算，因此普通输入框单击改为独立定位，避免粘贴依赖一次不必要的光标范围调用。图标只删除 IconSource.Foreground 并不能验证实际生成控件的颜色或路径缩放。

## 用户试用

1. 在旧版本托盘恢复全部窗口并退出，再启动第七轮 `GhostSlacking.App.exe`。不要同时运行旧版和新版；不覆盖第六轮目录。
2. 检查实验图标与相邻图标的颜色、线条与大小，分别切换浅深主题、展开/收起、选中/悬停和屏幕缩放。
3. 以 `tools/background-focus-probe.html` 为前台 A，选择空白测试对话 B 进入 Ghost/Reveal。完整记录本轮开始和结束时间。
4. 点击 B 的输入框后 Ctrl+V 粘贴无敏感信息的中文/英文/多行纯文本，观察内容和编辑器状态（例如发送按钮是否正确可用）。本工具不会自动发送，发送功能由用户按需人工验证。
5. 第二次粘贴及对已有草稿、空格、换行尝试粘贴，预期提示“仅限空框”；带附件/嵌入内容或无法确认结构时应拒绝。按钮点击后直接粘贴应要求重新点击输入框。
6. 验证侧栏等常用按钮、列表选择与展开操作；拖出按钮后返回再松开不得触发。会创建原生弹窗或主动抢焦点的动作可能触发现有收起保护，不记为成功。
7. 记录 B 的实际结果、A 的完整 blur/focus/visibility/hasFocus 记录和程序日志。只有 B 正确且 A 全程通过，停止后无卡键/样式残留，才能在下表写“通过”。不要因日志成功或最终焦点回到 A 就判定通过。

## 下一轮的进入条件

先根据第七轮真实反馈区分命中失败、模式不支持、空白/富内容拒绝、执行无效果、编辑器状态未更新和真实失焦。第八轮优先找已有草稿中的真实插入；第九轮仅在外部接口不足时评估真实目标的可选桥接。研究工具已有独立证据，但不自动对真实应用尝试 MSAA、原生根窗口消息、调试连接或额外启动参数；写入结果不确定时不尝试下一条路线。
