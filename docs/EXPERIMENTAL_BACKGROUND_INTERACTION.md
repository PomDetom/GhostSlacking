# 实验性 Reveal 后台交互

默认关闭的兼容性原型：尝试操作 Reveal 中的目标 B，同时保留前台 A 的焦点。后续目标是研究面向各类程序的通用机制；当前按控件分流的实现不代表通用兼容，也不保证网站无法检测切屏。实际兼容性及待完成项只维护在[实施状态](IMPLEMENTATION_STATUS.md)。

## 开启与操作

1. 从旧副本托盘恢复全部窗口并退出，再启动所要测试的版本，不同时运行多个副本。
2. 设置 → 实验性功能，开启“后台交互”。“显示”页将 Peek 设为“按下切换”，建议 F8 等独立按键，避免与交互快捷键组成键冲突。
3. 自动开始：开启“持续交互”并保存。手动开始：保持持续选项关闭，配置交互快捷键，先显示 Reveal 再按该键。
4. A 打开[焦点诊断页](../tools/background-focus-probe.html)并保持前台；选择无敏感内容的目标 B，隐藏 B，把光标移回其原范围后 Peek。
5. 若提示“先点前台”，B 继续隐藏且尚未拦截输入。点击 A 后把光标移回 B 会自动继续；有效前台满足且原按键释放后才准备并显示“交互中”。准备期间新输入被消费，不会延迟重放。
6. 持续模式中移出 B 正常结束，未关闭 Peek 时返回可重新准备。再次 Peek 关闭；交互快捷键结束并收起本次 Reveal，持续选项保持开启。
7. 真实失焦、目标失效、投递失败或未管理弹窗会收起并取消显示意图；必须重新手动 Peek，不循环重试。未支持操作只消费并提示，不等于已成功执行。
8. 设置、选窗、恢复和退出都会取消等待/准备/交互。“请先恢复”表示清理失败，应恢复当前或全部窗口。

持续模式只支持 Toggle Peek，持续 + 按住显示无法保存；外部写入该异常组合也会阻止 Reveal，不退回普通点击。关闭实验总开关保留持续选项但不生效，两项默认均关闭。

## 当前能力与限制

| 操作 | 当前边界 |
| --- | --- |
| 鼠标/文本 | Scintilla、Edit/RichEdit、UIA 使用不同控件机制；其他通用消息可能使目标激活。当前 UIA 语义按钮仅尝试单击、选项、展开等提供者能力，不保证真实应用有效。 |
| 英文输入 | 固定 US 英文路径，不切换 A 的系统布局。普通字符、编辑键能力取决于接收控件。 |
| 中文组合输入 | 未接入正式程序；单独 Shift、Ctrl/Win+Space、IME/死键及部分系统组合被消费并提示受限，不转给 A。独立研究原型不是已可用输入法。 |
| 复制/粘贴 | Scintilla 由目标控件处理剪贴板；UIA 正文可尝试纯文本复制。显式 Ctrl+V 只试验精确空白、可写且无未确认富内容的 Edit/ValuePattern；已有草稿、空格、换行、附件或身份不明时拒绝，不整框重写。 |
| 清理 | 停止只释放实际投递的按下状态；尾部最多两秒，保留准备前属于 A 的抬起。恢复开始后不再追加隐藏。 |
| 权限/隐私 | 不注入、不抓屏、不记录正文或剪贴板；必要文本只短暂留在操作内存。无默认提权。超时后的已发操作不能撤销或自动重试。 |

HUD 短提示表示会话/能力状态，不是焦点验证结果。“准备交互”表示尚在准备，“正文受限/仅限空框/内容受限”等表示能力限制，“失焦收起”表示检测到前台变化。工具不会自动发送聊天消息。

## 验收与研究入口

[实施计划的后台交互矩阵](IMPLEMENTATION_PLAN.md#94-实验性后台交互)列出首次启动、持续模式、鼠标/文本、保护条件和停止清理步骤。通过必须同时满足 B 操作正确、A 完整焦点记录正常和结束清理正常；最后切回 A 不足以证明全程未失焦。

- [独立控件/Chromium 探测工具](../tools/BackgroundInteractionProbe/README.md)：UIA、原生 Edit、MSAA 和隔离 CDP，限定在自己的测试窗口/隔离浏览器，不自动连接真实目标。
- [中文输入研究原型](../tools/BackgroundImeProbe/README.md)：系统 TSF 与独立小词表，未接入正式输入路径，生产可用性未验收。

当前实现细节由[架构文档](ARCHITECTURE.md#4-实验性后台输入)维护；真实问题和研究顺序由状态文档维护，不按历史轮次重复记录。
