# 实验性 Reveal 后台交互

这是本机现有窗口的兼容性原型，默认关闭。目标是操作 Reveal 中的 B，同时保持浏览器 A 的前台焦点；不保证任意应用完整兼容，也不保证任意网站无法检测切屏。真实应用矩阵由使用者验收。

## 开启与试用（第七轮）

1. 先从旧程序托盘恢复全部窗口并退出。单实例锁会阻止另一个副本启动，不需要卸载旧安装。
2. 启动 `artifacts/background-interaction-round7/GhostSlacking.App.exe`。前六轮目录和第四轮中文原型保留，请勿误启动旧副本。
3. 设置 → 实验性功能 → 开启“后台交互”。此页位于“常规”之后，使用单色烧瓶图标，没有新增托盘入口。
4. 在“显示”将 Peek 设为“按下切换”，建议使用 `F8` 等独立按键；不要将交互快捷键的组成键设为 Peek。
5. 开启“持续交互”并保存，随后关闭设置。也可关闭持续交互，仅绑定“交互快捷键”，沿用每次手动开始的方式。
6. 在浏览器 A 打开[焦点诊断页](../tools/background-focus-probe.html)，选择 Notepad++ 空白文档 B 并使其进入 Ghost。对照验证两种顺序：隐藏后直接 Peek，以及先聚焦 A、重置诊断记录再 Peek。
7. 光标移到 B 原位置后按 Peek。若前台为空或仍属于隐藏的 B，目标继续隐藏并显示“先点前台 / Focus first”，此时尚未拦截输入，可正常点击 A。聚焦 A 后把光标移回 B 范围，会自动继续，无需第二次 Peek。有效独立前台已满足时直接准备；松开已有按键后显示 Reveal 与“交互中”HUD。准备期间的新点击、滚轮和输入被消费，不排队重放。再次 Peek、设置、选窗、恢复、退出或目标失效会取消等待。手动模式仍需先显示 Reveal，再按交互快捷键。
8. 持续模式中，正常关闭 Peek 或移出 B 静默结束；只移出而未关闭 Peek 时，光标返回会自动准备并交互。交互快捷键结束会话并收起 Reveal，持续开关保持开启，下次手动 Peek 仍自动交互。
9. 真实失焦、投递失败、目标失效或未管理弹窗收起后，当前显示意图会清除，不循环重试。必须重新手动 Peek。未支持的输入只显示短提示并消费操作，保持会话。
10. 用 A 的完整事件记录与 B 的操作结果共同验收。“请先恢复”表示清理失败，应恢复当前/全部窗口。停止时只释放实际投递的按下状态，尚未松开的物理输入由尾部拦截消费；准备前已属于 A 的按键抬起仍交给 A。

持续交互默认关闭；配置 schema 10 新增 `ContinuousBackgroundInteraction`，旧配置保持手动行为。关闭后台交互总开关保留持续选项但不生效。启用持续交互且使用按住显示时不能保存；外部写入的异常组合也会阻止 Reveal，不退回普通点击。设置、选窗、恢复和退出会取消准备及交互；恢复开始后不追加隐藏操作。完整快照和 Watchdog 协议不变。

本功能不切回 A 来掩盖失焦，也不能撤销已发生的浏览器事件。最低要求 Windows 10 1607。

## 第七轮新增与用户验收

独立探测工具验证了标准 Edit、MSAA 和隔离 headless Chromium 的部分路径；这些研究不等于真实目标支持，也不会自动改其启动参数或建立连接。

## 第六轮新增与用户验收（历史）

通知宽度随内容调整，设置中的“宽度”改称“最大宽度”，旧保存值直接沿用为上限。短通知可小于 100 DIP；仍使用 18 DIP 图标、9 DIP 间距、两侧 10 DIP 内边距及单行文字，图文整体居中。高度、圆角和位置设置继续有效；预览与运行时共用测量，检查短长文字切换和不同 DPI 下的位置及留白。

ChatGPT 后台粘贴仍明确受限：日志 `PasteUnavailable` 表示当前适配器只开放定位、拖选及复制，没有尝试执行 Ctrl+V。第五轮后用户反馈不再失败，不等于粘贴能力已实现。完整原因、边界及本轮验收见[第六轮报告](BACKGROUND_INTERACTION_ROUND6.md)。

## 已实现与明确限制

| 项目 | 原型行为与限制 |
| --- | --- |
| 显示/鼠标 | 保留 region/羽化和 `WS_EX_NOACTIVATE`，物理按钮/滚轮不进入普通点击路径。Scintilla 使用定位和选区命令；Edit 使用原生文本命令；Chromium/Electron 等语义正文使用 UIA，不回退根窗口点击。其余应用可能走通用后台消息并自行激活，发生时收起。 |
| 基本键盘 | 固定美式英文映射，不加载或切换系统键盘布局。优先使用已加载的标准 US 布局做只读翻译，不存在时使用字母、数字、标点映射表。普通字符只发送 `WM_CHAR`，不再附加产生重复字符的按键消息；读取翻译结果严格使用返回长度。字符/编辑命令没有原生按下状态，不会在退出时额外发送抬起消息。 |
| 中文/日文/韩文组合输入 | 中文布局不再整类拒绝基本英文输入，但不启用拼音候选词或 IME/TSF 组合。特殊 IME 输入、死键和未适配系统键被消费并提示，不结束会话，也不转交前台 A。 |
| Scintilla 编辑键 | 方向键、Home/End、PageUp/PageDown、退格、Delete、Enter、Tab/Shift+Tab、Shift 选择、Ctrl+Left/Right、Ctrl+Home/End，以及 Ctrl+A/C/X/V/Z/Y、Ctrl+Shift+Z 使用控件自身命令。剪贴板由目标处理，只在用户实际按下对应快捷键时调用；程序不读取或记录剪贴板。 |
| 通用编辑键 | Edit/RichEdit 增加专用复制粘贴，UIA 正文可尝试选区和纯文本复制；第七轮输入框独立定位、仅试验严格空白框赋值，已有草稿中的光标插入仍受限。其他控件无适配的组合操作明确拒绝，不宣称所有应用已支持。 |
| 程序热键 | 通过会话钩子识别已配置且无冲突的程序热键，先结束会话再执行；后台交互快捷键结束并收起 Reveal，不立即重新开启。 |
| 编辑区外/弹窗 | Scintilla 窗口内的边栏、工具栏、右键及未适配鼠标组合仅提示不支持，不回退激活路径。非客户区或无法确定接收者的输入仍收起。可见 owner 弹窗、禁用目标或菜单循环会结束；不修改新顶层窗口。 |
| 焦点与诊断 | 记录前台事件、控件类、适配器、目标线程焦点 HWND、输入类别与具体拒绝原因，不记录字符。首次前台变化也会收起，不假装是“预热”。输入拒绝与实际失焦使用不同 HUD 提示。 |
| 内容与权限 | 不注入、不抓屏、不记录窗口文字、剪贴板或键盘内容。显式 Ctrl+V 可短暂读取 Unicode 文本并核对空白输入框，内容不持久化。不提升权限，跨权限输入失败会停止。 |

HUD/托盘代表会话状态，不能充当“网站未检测到切屏”的证明。网页自身 DOM 焦点、浏览器可见性、遮挡与自定义检测须结合诊断页和实际页面验收。右键菜单等在创建时就可能抢焦点，停止机制只能报告，不能撤销已经发生的失焦。

## 兼容性矩阵

当前逐应用/操作矩阵见[第五轮报告](BACKGROUND_INTERACTION_ROUND5.md#应用与操作记录)，第四轮历史矩阵保留。第五轮真实结果均待用户实测；旧版本失败或单纯不再收起均不算本轮通过记录。每项记录 Windows/应用版本、DPI、完整焦点证据及时间区间。

- **通过**：B 结果正确，A 全程 `hasFocus=true`，无 `blur` 或隐藏变化，系统前台无异常变化，结束后无卡键和样式残留。

- **不支持**：操作无效、错误接收输入、A 曾失焦/隐藏，或触发不兼容退出。不能因 A 最终回到前台而记为通过。

结束会话后主动切回 A 检查结果造成的事件，应按时间排除；窗口未聚焦就重置、日志截断或未覆盖完整测试时间都不能证明通过。焦点页 50ms 采样只补充事件，不能证明任意短暂状态都被采样捕获。
